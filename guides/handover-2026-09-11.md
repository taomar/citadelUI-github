## Architecture and important boundaries

The browser owns local directory handles and local source writes through the
File System Access API. Handles are browser-profile capabilities, not container
mounts. The server owns application persistence, Local transaction journals and
backups, GitHub operations, and encrypted credentials.

The container has no source repository mount, Docker socket or user cloud
credential. Never substitute server filesystem editing for browser-owned
source access.

`shared` contains reusable transformations and format handling, but not every
shared module is pure: some accept injected reads or initialize packaged parser
assets. The one-line server Bicep/doclayer modules are intentional re-exports.

## Accepted reliability fixes

### F1: Local receipt reconciliation

Ordinary Local writes and History Complete share `commitLocalReceipt`.
After an ambiguous receipt response, inspect the durable result rather than
assuming failure or blindly repeating a mutation.

A confirmed commit retains the final source bytes and returns explicit applied
metadata plus truthful warnings, including an audit-pending warning where
appropriate. Unknown status retains the bytes and surfaces explicit recovery.
Pre-receipt rollback remains separate and hash guarded.

History Complete no longer performs an illegal repeated failure transition for
an already failed/recovery-required journal. Terminal-recording and inspection
failures remain visible. The UI preserves confirmed warnings after History
refresh rather than clearing them with ordinary progress status.

### F2 and F3: Draft, quarantine and review identity

Quarantine is memory-only and independently retained per document/workspace
configuration. Repeated catalog/reopen and explicit discard do not resurrect
discarded data or erase the only remaining retained copy.

Workspace tickets, document generation, source path/hash, policy revision,
review epoch and modal frame identity are distinct. Do not replace them with
one universal counter.

Policy reviews capture the reviewed payload and identity before the asynchronous
preview starts, not at Save click. New edits during preview, after review opens,
or during an already-started durable save are retained or require re-review.
Old success and error feedback must not open a review over another document
or replace its status.

### F4: Explicit mutation outcomes and view effects

`applied`, `unchanged`, `pending`, `indeterminate` and `recovery-required`
are preserved through service, provider, API and UI layers. Unknown or pending
is not success, does not clear drafts, and does not authorize automatic retry.

A confirmed mutation followed by a failed UI refresh remains a confirmed
mutation. Creation/copy actions bind their actual destination and preserve
explicit branch choice, cancellation and retry behavior.

The final creation-Undo correction captures document ownership before
confirmation and restore. Both catalogs still refresh after actual deletion,
but template fallback is allowed only while the original view owns it.
Navigating to Beta while an already-durable Undo result is delayed no longer
steals Beta's selection, focused input or queued/unblurred drafts.

That final proof did not claim identity of every Beta status-text value.
Preserve the exact accepted boundary rather than describing universal timing
correctness.

### F5: GitHub reconciliation and attribution

A reachable audited earlier application can be recognized as a retry and
attributed to its actual commit, transaction and author, including a null author.
Current collaborator content equivalence is an unattributed no-op.

An unaudited historical ancestor that was later reverted is not proof of
successful application. Keep reviewed parent/blob/mode checks, audit ordering,
non-forced ref updates, bounded reachability and explicit alternate-branch
decisions. Do not create unsolicited recovery branches or private audit copies
of source.

### F6: Reversible source bytes

Non-native editable source uses strict UTF-8 with explicit BOM provenance.
CRLF, Unicode, backups and untouched source bytes remain reversible. Malformed
UTF-8 and unencodable changes are rejected.

Native admission, whole-file sensitivity, parser limits and BOM refusal remain
separate. Do not replace them with a permissive generic codec.

### F7: Exact encoded request budget

The public aggregate GitHub request limit is exactly 12 MiB, or 12,582,912 bytes
of encoded JSON, including base64, framing, metadata and native proofs.
The separate 8 MiB per-file and 64-file limits remain.

Client preview, submitted request and server checks use the accepted shared
contract. Boundary plus one byte must be refused. Public callers cannot opt out.
Server-generated inverse History commits have a separate internal transport
path, not a public bypass.

  unexpected external bytes remain undecided. Native and ordinary Bicep
